# PS2 backend cvars

Every cvar registered by the PS2 backend under [src/ps2/](src/ps2/), with its default in the
debug (`make`) and release (`make release`) builds. See the [README](README.md) for the
bigger picture. QuakeSpasm's own cvars are not listed here, including the ones the backend
registers in place of the QuakeSpasm files it replaced (`gamma`, `r_lerpmodels`, the `joy_*`
cvars, ...). Where one of those means something different on the PS2 (`joy_enable`,
`in_debugkeys`, the Options page's Look Speed, Invert Look and Stick Look rows over `joy_*` and
`+mlook`), the README's section on that subsystem says so.

- **Arch.** marks `CVAR_ARCHIVE` cvars: they are written to `config.cfg` and read back on
  the next boot, so the value in your config, not the default, is what a run starts with.
- **—** in the release column means the cvar is not registered at all there: the code that
  reads it is compiled out with `PS2_QUAKE_DEBUG` / `PS2_QUAKE_PROFILE`. Archived cvars never
  get a **—**. Every build registers them, even where nothing reads them, because the quit
  drops an archived cvar the build never registered from `config.cfg`.

More come back as each subsystem is ported.

| Cvar | Debug | Release | Flags | Description |
| --- | --- | --- | --- | --- |
| `ps2_gs_latency` | 1 | 1 | Arch. | 1 leaves each frame drawing on the GS and shows it at the start of the next, so the GS rasterises while the EE builds the next frame, for one frame of input lag. 0 waits for the GS and flips at the end of each frame. Live. On the Video Options page. |
| `ps2_fb_dither` | 0 | 0 | Arch. | The GS's ordered dither, which hides the banding of a 16-bit framebuffer on gradients. Live. On the Video Options page. |
| `ps2_fb_16bit` | 1 | 1 | Arch. | 16-bit (5:5:5) framebuffers instead of 32-bit: 560 KB of VRAM each instead of 1120 KB (640 KB and 1280 KB at PAL's 512 lines), which the texture heap gets. Read once as the GS comes up, from `config.cfg` (or `+ps2_fb_16bit 0` on the command line), so a change applies on the next run. On the Video Options page. |
| `ps2_video_mode` | auto | auto | Arch. | The TV standard: `auto` (the console's own, from its BIOS ROM name), `ntsc` (59.94 Hz, 640x448) or `pal` (50 Hz, 640x512). A PAL console can drive NTSC if the TV takes 60 Hz. Read at boot, as `ps2_fb_16bit` is, so a change applies on the next run; the error screen follows it too. On the Video Options page. |
| `ps2_screen_x` | 0 | 0 | Arch. | Where the picture sits on the TV: pixels to the right (negative: left) of the standard's usual place, -32 to 32, for a set that cuts an edge off. The GS DISPLAY register's origin moves, nothing is redrawn, and the picture clips where it meets the blanking. Live, and read ahead of the configs so the GS comes up with it; the error screen follows it too. On the Video Options page (Screen X), which marks the picture's edge while the row is under the cursor. PCSX2 ignores it unless its `pcrtc_offsets` setting is on. |
| `ps2_vsync_spin` | 0 | 0 | | Wait for vsync by spinning on the GS status register, as every build before 2026-11-01 did, instead of sleeping on the vblank interrupt. An A/B switch: the sleep gives the frame's idle time (8-11 ms a field) to the other threads, the sound feeder and the background loader. Live. |
| `ps2_screen_y` | 0 | 0 | Arch. | As `ps2_screen_x`, rows down (negative: up), -16 to 16: the room above the picture is a few lines on NTSC before it clips. On the Video Options page (Screen Y). |
| `in_keyboard` | 1 | 0 | Arch. | The USB keyboard, a development tool here. Its IOP driver (usbd and ps2kbd) loads the first time this is on: at boot it is read from `config.cfg` ahead of time, so with it off there the driver never loads. Switching it off lets go of any keys the keyboard holds. Each poll is a file read on the IOP, so it is read every frame only while in use (a key in the last 10 s, or one held) and every 250 ms otherwise, and not while a music read is out. Live. |
| `ps2_savedevice` | mc | mc | Arch. | Where save games go: `mc`, the memory card in MEMORY CARD slot 1, or the drive the game booted from, `usb` (a USB drive), `hdd` (the hard disk) or `host` (the emulator's `host:` filesystem), in `<gamedir>/save/` there. Every device holds the same compressed slot files, under the same notice. A value naming a drive the game didn't boot from means the card. `config.cfg` follows it (see the README's Save games section). `ps2_saveinfo` shows where saves are going and lists them. On the Options page (Save Device), which steps between the card and the boot drive. |
| `in_rumble` | 1 | 1 | Arch. | The pad's vibration: bursts for the player's shots, damage taken (stronger the harder the hit), pickups and powerups coming on. Off in menus, the console, demos and while paused. Live. On the Options page (Rumble). |
| `in_rumbledebug` | 0 | 0 | | Prints each rumble effect as it starts, with its motor speeds and durations. |
| `ps2_mip_filter` | bilinear | bilinear | Arch. | How the walls filter, as QuakeSpasm's `gl_texturemode` does: `nearest`, `bilinear` (between texels, the nearest mip level) or `trilinear` (between levels too, at twice the texture reads). Live. On the Video Options page. |
| `ps2_dynamic_lights` | lightmaps | lightmaps | Arch. | How the walls take the dynamic lights while `gl_flashblend` is 0: `lightmaps` rebuilds the luxels they reach and re-uploads their atlases, as QuakeSpasm does; `vertex` leaves the lightmaps alone and has VU1 add the four lights nearest the camera at each vertex of the lightmap pass (the Quake II port's `ps2_dynamic_lightmaps 2`). The vertex lights add a flat colour beside the texture rather than brightening it, light big faces only at their corners, and light brush entities in their own space. Alias models are lit by every light either way. `r_dynamic 0` turns both off. Live. On the Video Options page (Dynamic lights), whose third value, glows, is `gl_flashblend 1`. |
| `ps2_dlight_scale` | 0.15 | 0.15 | Arch. | The brightness of `ps2_dynamic_lights vertex`: a light adds its radius times this at its centre, in GS colour (128 is the texture's own), falling off with the distance squared to nothing at its radius. At 0.5 a rocket's muzzle washed e1m1's corridor near white. Live. |
| `ps2_mip_bias` | 0 | 0 | Arch. | Shifts the mip levels the walls sample, in levels; positive is blurrier. The GS picks a level by depth alone, so floors seen at a grazing angle come out sharper than their texel density calls for. Live. |
| `ps2_st_rebase` | 1 | 1 | Arch. | Moves each wall face's texture coordinates by whole repeats so the smallest starts in [0, 1). id's projection gives them relative to the texture's world origin, tens of repeats out, and a console's GS loses precision on large values: walls drew stretched or swam on the Quake II port's hardware runs. The same texels are sampled either way; 0 keeps id's coordinates. Applies on the next map load. |
| `ps2_logfile` | 0 | 0 | | 1 by default in a build with `PS2_QUAKE_LOAD_TRACE` set to 1 (load_trace.h). Copies everything the console prints, plus a `Sys_Error` and the reports printed on the way to one (the debug build's EE exception report, render pipeline hang dump and stack traces, the out-of-memory stats), to `quake.log` next to `id1/` (`build/<config>/` on `host:`, the game data's folder on the HDD or the USB drive), each line stamped with the seconds since `main()`. The log opens with the IOP boot report. Until this is on, the first 16 KB of output waits in RAM and goes in first, so a log turned on from `autoexec.cfg` or the console still starts at boot. Every line opens, appends to and closes the file, the only flush a FAT drive has: about 23 ms a line over USB on the Quake II port's console. Not archived, so a session that wants it sets it. Live. |
| `ps2_debug_overlays` | 1 | 0 | Arch. | Master switch for the debug panels below, all but the FPS counter. Each panel also has its own switch, on in every build, so this alone brings them up. On the Video Options page. |
| `ps2_show_fps` | 1 | 0 | Arch. | FPS counter, top right: green while every frame made its vsync, yellow once one missed, red at half the refresh rate or below. On the Video Options page. |
| `ps2_show_profile` | 1 | 1 | Arch. | Frame times per profiled event, under the FPS counter. Draws in profile builds only. |
| `ps2_show_memstats` | 1 | 1 | Arch. | Heap use per memory tag, with the total, its peak and what is left, bottom right. |
| `ps2_show_vramstats` | 1 | 1 | Arch. | GS texture heap use and its peak this run, resident textures, and this frame's uploads and forced GS drains, bottom left. |
| `ps2_show_drawstats` | 1 | 1 | Arch. | What the last frame submitted (triangles, particles, batches, clipping) and the DMA chain's use, top left. Draws in profile builds only. |
| `ps2_frame_log` | 0 | — | | Writes per-frame timings and draw counters to stdout as CSV `FLOG` rows, for `src/tools/scripts/frame_log/`. A build with `PS2_QUAKE_FRAME_LOG_FILE=1` (profile.h) appends them to `id1/frame_log.txt` as well, for a console. The `FLOG#open` lines naming each file opened are only written during a `ps2_perftest` run or the perf pass of `ps2_testmaps`. Registered in profile builds (`PS2_QUAKE_PROFILE`). |
| `ps2_testmaps` | 0 | — | | Loads every level in the game data's paks: the campaign in play order (start, each episode, end; the shareware pak0 has start and episode 1, the registered pak1 the rest), then any others alphabetically (pak1's deathmatch maps). It starts by saying how many it found and which campaign maps the data lacks, and prints what each level costs as it leaves it: QuakeSpasm's hunk and cache and what is left of it, the backend's level data by memory tag, the heap's peak and the RAM still free; and the GS texture heap's peak in the level, what the level needed of it as if it never evicted (every distinct texture resident at some moment, counted once) with the evictions it took, and what every texture it loaded would take resident. **1**, the memory pass, stays `ps2_testmaps_dwell` seconds in each and ends with `MapCycle: done.`; `ps2_testmaps_restart` starts it over. **2**, the perf pass (it also needs a profile build), sets up a capture as `ps2_perftest` does, then in each level turns `god` and `notarget` on and turns a full circle (2 degrees a frame) at up to `ps2_testmaps_views` viewpoints, each after an `FLOG#view` marker. Either pass sets the cvar back to 0 at the end and quits, unless `ps2_test_quit` is 0. Don't combine with `ps2_perftest`. |
| `ps2_test_quit` | 1 | — | | Whether `ps2_perftest` and both passes of `ps2_testmaps` quit when they end. 0 leaves the game up, with the test's cvar back at 0, ready for the next test: how the debug page runs several in one session on a console. Not archived, so every boot starts at 1, as a test armed from `config.cfg` expects. Registered in debug and profile builds. |
| `ps2_testmaps_dwell` | 8 | — | | Seconds the memory pass of `ps2_testmaps` stays in each map once it has loaded. |
| `ps2_testmaps_views` | 5 | — | | Viewpoints the perf pass of `ps2_testmaps` visits in each level: where the player spawns, then each time the intermission camera, deathmatch start or teleporter exit farthest from those already picked. Up to 16; each takes about 3 seconds. |
| `ps2_perftest` | 0 | 0 | Arch. | An unattended performance capture: stops the attract loop, plays demo1, demo2 and demo3 once each with `ps2_frame_log 1`, the file-open notes on and the debug panels off, then puts `developer` and the panels back as they were, turns the frame log off and quits, unless `ps2_test_quit` is 0. Arm it in `config.cfg` or `autoexec.cfg`; it sets itself back to 0 at the end. Runs in profile builds only (`PS2_QUAKE_PROFILE`), but every build registers it, as it is archived. |
| `ps2_testcube` | 0 | — | | Draws the VU1 test cube on top of every frame: the GS/VU1 smoke test. |
| `ps2_testcube_tess` | 8 | — | | The test cube's tessellation per face, 1 to 8. Higher values push a face past one VU1 batch, to exercise chunked submission. |
| `ps2_testcube_vram_tex_eviction` | 0 | — | | Slides the cube's faces through the debug textures every 2 s, to exercise VRAM eviction. Use it with the heap shrunk (`kDebugHeapLimitWords` in `vram.cpp`). |
| `ps2_testcube_vulerp` | 0 | — | | Draws the cube through the keyframe-lerp path the alias models use instead, as a check of the VU1 unpack and lerp. |
